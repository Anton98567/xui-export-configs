# xui-export-configs

Universal exporter of **XHTTP (VLESS) + Hysteria2** client configs from a local
**3x-ui / x-ui** panel into one file — one share link per line.

Works on any VPS with 3x-ui (or x-ui) installed: no IP, domain or password is
hardcoded. The script reads the panel SQLite DB only to find the built-in
subscription server settings, then pulls every client's links from it on
`127.0.0.1` — no panel login required. Link generation is done by the panel
itself, so the output is exactly what clients should import.

## Quick start (after 3x-ui install)

```bash
curl -fsSL https://raw.githubusercontent.com/Anton98567/xui-export-configs/main/xui-export.sh | bash
```

Result: `/root/all.txt` with all xhttp + hy2 links, grouped by client.

## What it does

1. Finds the panel DB (`/etc/x-ui/x-ui.db`, `/usr/local/x-ui/x-ui.db`,
   `/opt/x-ui/x-ui.db`, or `XUI_DB=/path/to/x-ui.db`).
2. Reads subscription settings (`subPort`, `subPath`, `subListen`, `subEnable`)
   and the list of client `sub_id`s (supports both new `clients` and old
   `client_traffics` schemas).
3. Fetches each client's subscription from the built-in sub server and decodes
   the base64 link list.
4. Filters links: `vless://...type=xhttp` and `hysteria2://` / `hy2://`
   (plus legacy `hysteria://`).
5. Writes everything to the output file, grouped by client.

## Usage

```bash
bash xui-export.sh
```

Environment variables:

| Variable   | Default         | Meaning                                          |
|------------|-----------------|--------------------------------------------------|
| `OUT`      | `/root/all.txt` | output file                                      |
| `KEEP_ALL` | `0`             | `1` = export every link, not only xhttp + hy2    |
| `XUI_DB`   | (auto-detect)   | explicit path to `x-ui.db`                       |

Examples:

```bash
# custom output file
OUT=/tmp/configs.txt bash xui-export.sh

# export ALL protocols (trojan, vmess, etc. too)
KEEP_ALL=1 bash xui-export.sh
```

## Example output

```text
########## user1 (sub_id: a1b2c3d4e5f6) ##########
vless://<uuid>@<host>:443?...&type=xhttp&...#VLESS%20xHTTP
hysteria2://<password>@<host>:443?...#Hysteria%202

########## user2 (sub_id: f6e5d4c3b2a1) ##########
...
```

## Requirements

- bash, curl, base64 (coreutils) — present on any Linux VPS;
- `sqlite3` **or** `python3` — to read the panel DB (python3 stdlib only);
- run on the VPS itself (it talks to the sub server on localhost);
- the built-in subscription server must be enabled in the panel
  (Settings -> Basic -> Subscription). It is enabled by default in 3x-ui.

## Notes

- Disabled clients are skipped; a client with no `sub_id` cannot be exported.
- The file contains raw share links (with secrets) — keep it private.
- Exit code is non-zero if nothing was exported.

# xui-pastebin-upload.sh

Upload a file (default: `/root/all.txt`) to **pastebin.com** as a
**password-protected** paste.

Pastebin's API cannot create natively password-protected pastes (that is a
web/Pro feature), so the script encrypts the content first
(**AES-256-CBC + PBKDF2-SHA256** via openssl) and uploads the ciphertext as an
**unlisted** paste. Without the password the paste content is unreadable —
no public access to the configs. The script verifies the uploaded copy by
downloading and decrypting it back.

## Quick start

```bash
curl -fsSL https://raw.githubusercontent.com/Anton98567/xui-export-configs/main/xui-pastebin-upload.sh | PASTEBIN_DEV_KEY=<your dev key> bash
```

Or store the key once (kept out of the script and shell history):

```bash
umask 077 && printf %s "<your dev key>" > /root/.pastebin_key
curl -fsSL https://raw.githubusercontent.com/Anton98567/xui-export-configs/main/xui-pastebin-upload.sh | bash
```

Output (at the end):

```text
[xui-pastebin] URL:      https://pastebin.com/XXXXXXXX
[xui-pastebin] PASSWORD: <auto-generated>
[xui-pastebin] decrypt:  curl -s https://pastebin.com/raw/XXXXXXXX | base64 -d | openssl enc -aes-256-cbc -pbkdf2 -md sha256 -d -pass pass:'<PASSWORD>' -out all.txt
```

## Environment variables

| Variable          | Default           | Meaning                                    |
|-------------------|-------------------|--------------------------------------------|
| `FILE`            | `/root/all.txt`   | file to upload                             |
| `PASS`            | (random)          | password; auto-generated if not set        |
| `NAME`            | `encrypted-configs` | paste title                              |
| `EXPIRE`          | `N`               | `N`/`10M`/`1H`/`1D`/`1W`/`1M`/`1Y`         |
| `PASTEBIN_DEV_KEY`| —                 | API dev key (or `/root/.pastebin_key`)     |

## Requirements

- bash, curl, openssl (1.1.1+ for `-pbkdf2`), base64, cmp — standard on any VPS.
- A pastebin API dev key: https://pastebin.com/doc_api (free; limit 25 pastes/24h).

## Security notes

- The paste is **unlisted** and its content is **encrypted** — the link alone
  gives no access to the configs; the password is shared separately.
- The API key is never hardcoded: pass it via `PASTEBIN_DEV_KEY` or
  `/root/.pastebin_key` (chmod 600).
- Treat the printed password as a secret; rotate it by re-running with a new
  `PASS` (and deleting the old paste if needed).

# pb-share.sh — password-protected paste with plain-text view

The exact "link + password + plain text" flow. Unlike pastebin.com (whose API
has **no password parameter at all** — see their `doc_api`), **PrivateBin**
gives a real password-gated paste: the recipient opens the URL, types the
password, and reads the file as ordinary text. No encrypt/decrypt commands.

How it protects the configs:
- content is encrypted in the browser with **AES-256-GCM** (zero-knowledge);
- the **password is a second layer on top of the link** — neither the link
  alone (decryption fails with `MAC check failed`) nor the password alone is
  enough;
- displayed as **plaintext** (not an encrypted blob).

## Quick start

```bash
curl -fsSL https://raw.githubusercontent.com/Anton98567/xui-export-configs/main/pb-share.sh | bash
```

Or with options:

```bash
PB_EXPIRE=1day bash pb-share.sh /root/all.txt     # custom file + expiry
PB_BURN=1 bash pb-share.sh                        # burn after first read
PB_URL=https://your-privatebin.example bash pb-share.sh   # self-hosted instance
```

Output:

```text
[pb-share] done
URL:      https://privatebin.net/?<id>#<key-fragment>
PASSWORD: <auto-generated or yours>
```

Send the recipient **both** the full URL (keep the `#fragment`) and the
password. They open the URL, enter the password, and see the file as text.

## Environment variables

| Variable      | Default                   | Meaning                              |
|---------------|---------------------------|--------------------------------------|
| `FILE` / `$1` | `/root/all.txt`           | file to upload                       |
| `PB_URL`      | `https://privatebin.net`  | any PrivateBin instance              |
| `PB_PASSWORD` | (random, 20 chars)        | paste password                       |
| `PB_EXPIRE`   | `1week`                   | `5min`/`1hour`/`1day`/`1week`/`1month`/`1year`/`never` |
| `PB_BURN`     | `0`                       | `1` = delete after first read        |
| `PB_VENV`     | `$HOME/.pbshare-venv`     | python venv location                 |

## Account needed?

**No.** A public PrivateBin instance needs no account and no API key. For full
control over your data, self-host PrivateBin (https://privatebin.info — a small
PHP app, one Docker container) and set `PB_URL` to your own domain.

## Requirements & notes

- `python3` (+ venv) on first run; installs `privatebinapi` + `cryptography`
  into a local venv automatically. Needs internet for the first install.
- The script **verifies the round-trip**: it downloads the paste back, decrypts
  it with the password and compares to the source before printing success.
- The share URL contains a `#key-fragment` — it is required for decryption, so
  send the complete URL. The password adds a second gate on top of it.
- `privatebinapi` is the reference Python client for PrivateBin's API; pastes
  are readable in any browser (no special client needed by the recipient).
